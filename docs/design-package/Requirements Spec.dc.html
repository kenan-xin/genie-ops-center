Genie Control Station · Product Specification

Functional & Non-Functional Requirements

Source  Genie Control Station.dc.html (prototype) Status  Derived from current build Revision  Jun 2026

This specification is reverse-engineered from the working prototype and describes the behaviour as currently implemented. It covers two surfaces: the customer workspace (the Demo Hub and Solution Viewer that can be handed directly to a prospect) and the Admin Portal (a separate console reached only through the admin sign-in). Requirement IDs are stable handles for traceability; behaviours marked (demo) are scaffolding that a production backend would replace.

01 Actors, roles & core concepts

The system serves three actor types and organises everything around solutions (deployable demos), groups (the unit of access), and people (users assigned to groups).

ROLE · Member
Customer-side user. Sees only the workspace and only the solutions granted through their groups. No admin affordances.
ROLE · Owner
Workspace Owner — elevated member who can also reach the Admin Portal via the separate admin sign-in.
CONCEPT
Solutions come in three types: Chat (conversational, themeable, configurable), Native (guided step wizard; not themeable, not configurable) and Embedded / Smart-API (embedded console; not themeable, configurable). Each carries a lifecycle status: Ready, Draft, Maintenance or Down.
CONCEPT
Access is granted to groups, never to individuals. A group is granted a set of solutions; people are assigned to groups; a person's reachable solutions are the union across their groups.

02 Authentication & session

All entry is gated by email + password sign-in, with a separate sign-in path for the Admin Portal.

FR-AUTH-01
Email + password sign-in
Both fields required; an empty field shows an inline error. A valid submission advances to the second-factor step.
FR-AUTH-02
Separate admin sign-in
The Admin Portal is reached only through a dedicated admin sign-in screen; on success the second-factor step routes to the portal rather than the workspace.
FR-AUTH-03
Forgot-password flow
Four steps: enter a valid-format email → "link sent" confirmation → set a new password (live strength meter; must reach at least "Good", confirmation must match) → success, returning to sign-in with a success notice.
FR-AUTH-04
Idle session timeout
After 15 minutes idle a modal warns with a 60-second countdown. "Stay signed in" resets the timer; the countdown reaching zero — or choosing to sign out — logs the user out.
FR-AUTH-05
Sign out
Clears all transient session state (open dialogs, flows, code entry, timers) and returns to the sign-in screen.
FR-AUTH-06
Password strength rule
Strength scores 0–4 across four checks: length ≥ 8, mixed upper/lowercase, a digit, and a symbol. New passwords must score ≥ 3.

03 Demo Hub (customer workspace)

The hub is the catalogue a prospect browses. Copy stays neutral — no internal/sales framing.

FR-HUB-01
Access-gated catalogue
Only solutions granted through a group the signed-in user belongs to are listed; archived solutions are hidden. A user with no granted solutions sees an empty state.
FR-HUB-02
Live name search
A search field filters the list by solution name as the user types, resetting pagination.
FR-HUB-03
Type filter
A segmented control filters by type: All / Chat / Native / Embedded.
FR-HUB-04
Sort
Results sort by Recent, Name, or Status.
FR-HUB-05
Progressive loading
The list starts at 5 rows and extends by 4 — both via an explicit "load more" action and automatically when the user scrolls near the bottom. A "N OF M SHOWN" counter reflects progress.
FR-HUB-06
Clear filters
A single action resets search, type and vertical filters and pagination.
FR-HUB-07
Solution row & openability
Each row shows a monogram, name, description, type label and a colour-coded status badge. Rows are openable only when the status is not Draft; non-openable rows are dimmed and not clickable.
FR-HUB-08
Favorites
A star toggles a solution as a favourite directly from its row, without opening it.
FR-HUB-09
Recent & Favorites views
Opening a solution records it to "recent" (most-recent first, capped at the last six; up to four surfaced on the hub). Dedicated Recent and Favorites pages are reachable from the nav, each honouring the same access gating.

04 Solution Viewer

The viewer renders the live experience for whichever solution type was opened, plus the chrome controls used when demoing.

FR-VIEW-01
Chat experience
Opens with a configurable greeting and a set of configurable starter prompts. The user sends messages with Enter or the send button; replies stream in character-by-character with a typing indicator. (demo) replies are keyword-matched canned responses.
FR-VIEW-02
Message feedback
Each assistant reply (other than the opening greeting) offers thumbs up / down; a down-vote shows a "thanks" toast; re-tapping the active choice clears it.
FR-VIEW-03
Native step wizard
Native solutions present a three-step guided flow — Upload → Processing → Results — with a Next control and the ability to reset to the first step.
FR-VIEW-04
Embedded (Smart-API) console
Embedded solutions render an external console. One designated solution simulates a flaky first load (error state) with a Retry that resolves after a brief delay; a reload control is always available.
FR-VIEW-05
Status gating in the viewer
Maintenance and Down solutions show a non-interactive status notice instead of the live experience; Draft solutions cannot be opened at all.
FR-VIEW-06
Presentation chrome modes
The viewer supports toggling the sidebar, a standalone mode (sidebar + header hidden), and a present / full-screen mode — each reversible back to the normal layout.
FR-VIEW-07
Offline awareness
The interface reflects the browser's online/offline state and surfaces an offline indicator when connectivity drops.

05 Account & security (customer)

Self-service account management with three sections: Profile, Password, Devices & sessions.

FR-ACCT-01
Profile
Displays an initials avatar, email and role; the display name is editable.
FR-ACCT-02
Change password
Requires the current password, a new password scoring ≥ 3 on the strength meter, and a matching confirmation; field-level errors block the save, and success confirms with a toast.
FR-ACCT-03
Devices & sessions
Lists active sessions with the current device marked. The user can sign out an individual device, sign out all other devices, or clear remembered devices — destructive actions confirm first.

06 Admin · People

FR-ADM-P-01
People directory
Lists name, email, role, status (Active / Disabled / Pending), group-membership chips and last-active. Searchable by name/email/role and sortable by name, role or status.
FR-ADM-P-02
Invite a person
Adding a person requires name and email and a role (Member or Workspace Owner); the new person is created in Pending state and an invite confirmation toast is shown.
FR-ADM-P-03
Edit a person
Name, email and role can be edited; changes are saved with a confirmation toast.
FR-ADM-P-04
Lifecycle actions
A person can be disabled / re-enabled; a pending person can be activated or re-sent their invite.
FR-ADM-P-05
Account-security actions
Guided flows let an admin reset a password (email a reset link, or set a temporary password with an optional force-change-on-next-login), reset MFA (require re-enrolment or email an enrolment link), or force sign-out of all the person's sessions. Each ends in a confirmation message and toast.
FR-ADM-P-06
Remove a person
Removal requires confirmation, takes effect immediately and strips the person from every group.
FR-ADM-P-07
Jump to group from person
From a person's record, an admin can open any of that person's groups directly in the group inspector.

07 Admin · Groups & Access

Groups are the single mechanism for granting access. Each group holds a set of solutions and a set of members.

FR-ADM-G-01
Group list
Lists each group with its solution count and member count; selecting a group opens its inspector. Searchable by name.
FR-ADM-G-02
Create / rename / delete
Groups can be created, renamed, given a description, and deleted (delete confirms and notes that members retain access only through their other groups).
FR-ADM-G-03
Group inspector
Within a group, an admin toggles individual solutions and members in or out, with grant-all / clear-all and add-all / remove-all bulk actions (the destructive bulk actions confirm) and per-list search.
FR-ADM-G-04
Solution-access transfer list
A dual-list (Available ⇄ Granted) for a chosen target group supports multi-select with select-all, grant/revoke of the selection, add-all / remove-all (remove-all confirms), and search on each side.
FR-ADM-G-05
Membership transfer list
The same dual-list pattern assigns people to a group (Available ⇄ Members).

08 Admin · Solutions

FR-ADM-S-01
Solutions table
Lists each solution with name, type and an inline status selector; searchable, type-filterable and sortable. Each row has an actions menu.
FR-ADM-S-02
Register a solution
A name is required; a type (Chat / Native / Embedded) and description are captured; a URL slug is derived from the name. New solutions are created as Draft.
FR-ADM-S-03
Configure a solution
Configurable solutions (Chat and Embedded) expose a welcome message, starter prompts and a feedback toggle; Chat solutions additionally bind to a theme and configure the chat streaming API endpoint they call for responses. Native solutions are not configurable. A live preview reflects the bound theme.
FR-ADM-S-04
Row actions
Duplicate (creates a Draft copy), archive / unarchive (hides from / restores to the hub) and delete (confirms; permanently removes and revokes the solution from every group).
FR-ADM-S-05
Status governs availability
Setting status to Ready, Draft, Maintenance or Down directly controls whether and how the solution can be opened in the customer workspace.

09 Admin · Overview & Theme Builder

FR-ADM-O-01
Access explorer
Two lenses: By solution — choose a solution and see which groups grant it and which people it therefore reaches; By person — choose a person and see their groups and the resulting solutions, each annotated with the granting group. Both offer shortcuts into the relevant group.
FR-ADM-T-01
Theme management
Themes can be listed, selected, created and deleted; only Chat solutions are themeable, and each chat solution is assigned one theme.
FR-ADM-T-02
Theme editing
Editing is organised into Presets, Elements (header colour, user-bubble colour, corner radius, font, input placeholder) and a Custom-CSS tab.
FR-ADM-T-03
Live device preview
Edits render live in a preview that toggles between desktop and mobile framing.

10 System feedback

FR-SYS-01
Toasts
Success and error actions surface a transient toast that auto-dismisses after roughly four seconds and can be dismissed manually.
FR-SYS-02
Confirmation dialogs
Every destructive action (delete, revoke-all, remove, sign-out, disable 2FA) routes through a shared confirmation dialog with danger styling before it commits.

11 Non-functional requirements

NFR-RES-01
Mobile-first responsive layout
The UI is built mobile-first and adapts across breakpoints at 480 / 768 / 920 / 1024 / 1280 / 1440 / 1920 / 2560 px. Below 920 px the sidebar collapses to an off-canvas drawer with a backdrop; above it the sidebar is persistent.
NFR-TYPE-01
Fluid type system
Eight role sizes derive from three base knobs (headings / body / labels) via fixed ratios; each breakpoint tunes only those three numbers. Typeface roles: Archivo (display), Hanken Grotesk (UI), IBM Plex Mono (data & labels).
NFR-THEME-01
Light / dark & brand theming
Full light and dark palettes are defined as CSS variables and toggle at runtime. Accent (blue / slate / forest / plum) and surface tone (cool / warm / sand) plus a default-theme choice are exposed as configurable properties.
NFR-A11Y-01
Accessibility
Visible focus outlines on inputs, honour of prefers-reduced-motion (disables the typing animation), and adequately sized touch targets are required.
NFR-PERF-01
Performance & smoothness
Long lists page progressively to bound the DOM; transitions stay short (≈150–220 ms); the chat stream renders incrementally without blocking input.
NFR-SEC-01
Security model
Idle session timeout and group-based authorization with no per-user solution grants. The Admin Portal is segregated from the customer workspace behind its own sign-in.
NFR-BRAND-01
Ledger visual language
Firm light/dark surfaces, square-ish corners, hairline keylines. Brand blue (#2360c4) is reserved for selection and primary actions; all other colour is semantic (success / warning / error).
NFR-CONTENT-01
Customer-safe copy
Because the workspace may be handed directly to a prospect, its copy stays neutral — no internal/sales framing and no admin affordances leak into the customer surfaces.
NFR-STATE-01
State & persistence (prototype)
The current build holds all state in memory for a single session with no backend; sign-in credentials, codes and data are demo scaffolding. Production requires a persistent identity, authorization and solution store.
Note
Behaviours tagged (demo) — canned chat replies, simulated embed flakiness, seeded users/solutions — exist to make the prototype self-contained and are expected to be replaced by live services. They are documented here because they define the intended interaction, not the final implementation.
